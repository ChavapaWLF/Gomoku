## 📖 项目简介

本项目实现了一个功能完整的五子棋游戏系统，支持人人对战、人机对战和机器自对弈三种模式，严格遵守五子棋国际标准规则（包括黑方禁手规则）。

**主要特点：**
- ✨ 支持多种对弈模式（人人、人机、机机）
- 🧠 基于Min-Max搜索算法的AI引擎，搭配Alpha-Beta剪枝优化
- 🚀 使用OpenMP实现多线程并行加速
- 📏 严格实现黑方禁手规则（三三禁手、四四禁手、长连禁手）
- 🎮 四档AI难度可选（初级/中级/高级/超级）
- 📊 内置开局库（花月、浦月等经典开局）
- 🎨 友好的终端界面显示

## 🎯 游戏规则

### 基本规则
1. **棋盘规格**：15×15交叉点
2. **获胜条件**：率先在横、竖或斜方向上连成五子者获胜
3. **先后手**：黑方先手，白方后手

### 黑方禁手规则
本程序实现了标准的RIF（Renju International Federation）禁手规则：

#### 1. 长连禁手
黑棋一子落下形成**六连及以上**的长连即为禁手，判负。

#### 2. 三三禁手
黑棋一子落下**同时形成两个或以上活三**即为禁手，判负。
- **活三**：指两端都未被堵住，再走一步可形成活四的三连
- **假活三**：虽然形态像活三，但实际落子后会触发其他禁手的三连（不计入三三禁手）

#### 3. 四四禁手
黑棋一子落下**同时形成两个或以上的四**（包括冲四和活四）即为禁手，判负。
- **活四**：两端都有空位，下一步必成五的四连
- **冲四**：只有一端有空位，下一步可成五的四连

#### 特殊说明
- **五连优先级高于禁手**：如果一步棋同时形成五连和禁手，则优先判定为五连获胜
- **四三不禁手**：一子同时形成一个四和一个三的情况不算禁手
- **白方无禁手**：以上禁手规则仅适用于黑方，白方无任何禁手限制

## 🚀 编译与运行

### 环境要求
- **操作系统**：Windows（推荐Windows 10/11）
- **编译器**：GCC (MinGW)
- **必需库**：OpenMP

### 编译指令

```bash
gcc -O3 -fopenmp -o gomoku main.c check.c display.c machine.c
```

**编译参数说明：**
- `-O3`：开启最高级别优化，最大化运算效率
- `-fopenmp`：启用OpenMP多线程并行计算
- `-o gomoku`：指定输出可执行文件名

### 运行程序

编译成功后，直接运行：

```bash
./gomoku
```

或在Windows下双击生成的 `gomoku.exe` 文件。

### Linux/macOS 适配说明

本项目在Windows环境下开发，使用了部分Windows特定的系统调用（如 `system("cls")` 清屏、`system("color f0")` 设置颜色）。如需在Linux/macOS环境下运行，建议：

1. 删除或注释 `display.c` 和 `main.c` 中的 `system()` 函数调用
2. 将 `system("cls")` 替换为 `system("clear")`
3. 删除控制台颜色设置相关代码

## 🧠 算法原理

### 1. Min-Max 搜索算法

Min-Max算法是一种零和博弈的决策算法，基于以下假设：
- 己方（Max层）总是选择收益最大的走法
- 对方（Min层）总是选择对己方最不利的走法

**递归过程：**
```
BestChoice(depth, color):
    if depth == 0:
        return Evaluate(board)
    
    if color == AI:
        max_value = -∞
        for each valid move:
            board.place(move)
            value = BestChoice(depth-1, opponent)
            board.undo(move)
            max_value = max(max_value, value)
        return max_value
    else:
        min_value = +∞
        for each valid move:
            board.place(move)
            value = BestChoice(depth-1, AI)
            board.undo(move)
            min_value = min(min_value, value)
        return min_value
```

### 2. Alpha-Beta 剪枝

Alpha-Beta剪枝通过维护当前搜索的上下界（Alpha和Beta）来减少不必要的搜索分支。

**剪枝条件：**
- 在Max层：如果当前值 ≥ Beta，则剪枝（父节点不会选择此路径）
- 在Min层：如果当前值 ≤ Alpha，则剪枝（父节点不会选择此路径）

**效果：**
- 理论上可将搜索节点从 $O(b^d)$ 降至 $O(b^{d/2})$
- 实际测试中剪枝率达到60%-80%

### 3. 局面评估

局面评估函数为棋盘赋予一个数值分数，分数越高对AI越有利。

**评估要素：**

| 棋型 | 价值 | 说明 |
|------|------|------|
| 五连（合法） | 50000 | 获胜 |
| 活四 | 4320 | 下一步必胜 |
| 冲四 | 720 | 必须防守 |
| 活三 | 720 | 可形成多个活四 |
| 冲三 | 100 | - |
| 活二 | 120 | - |
| 冲二 | 20 | - |

**计算公式：**
```
Score = Σ(己方棋型价值) - Σ(对方棋型价值 × 权重)
```

### 4. 候选点生成

为减少搜索空间，只考虑有意义的落子点：

**生成策略：**
1. 遍历棋盘上所有已有棋子
2. 在其周围2格范围内的空位作为候选点
3. 计算每个候选点的初步分数
4. 按分数降序排序，取前N个点（宽度控制）

**宽度控制：**
- 初级/中级：固定15个候选点
- 高级：根据搜索深度动态调整（16→15）
- 超级：深度越深，候选点越少（16→15→10）

### 5. OpenMP 并行化

在根节点（搜索深度最大时），对候选点进行并行搜索：

```c
#pragma omp parallel for schedule(dynamic)
for(i = 0; i < width; i++) {
    // 每个线程独立创建棋盘副本
    board_copy = copy_board(board);
    // 独立搜索子树
    value[i] = BestChoice(board_copy, depth-1, ...);
}
```

**优势：**
- 充分利用多核CPU
- 显著减少高难度下的思考时间
- 线程间无数据竞争

## ⚠️ 注意事项

1. **编译必须开启 `-O3` 优化**：否则运算效率极低，AI思考时间过长

2. **编译必须添加 `-fopenmp` 标志**：否则无法使用多线程并行，会导致链接错误

3. **超级模式思考时间极长**：
   - 深度12的搜索树规模巨大
   - 单步可能需要数分钟
   - 仅建议用于算法演示，不适合实际对弈

4. **Windows控制台限制**：
   - 部分终端可能不支持特殊字符显示
   - 建议使用Windows Terminal或PowerShell

5. **内存占用**：
   - 高级/超级模式运行时内存占用约500MB-1GB
   - 低配置设备建议使用初级/中级模式
